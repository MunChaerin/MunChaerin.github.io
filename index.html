  • Spring Boot API와 연동해 스팟, 스토리, 오디오, 컬렉션 아이템, 셀카 저장 흐름 구성

기술적 의사결정

지도 스팟 조회 API 구조 재정리

결정사용자 주변 반경 조회 API를 제거하고, 지도 진입 시 전체 스팟 조회 + 핀 클릭 상세 조회 구조로 단순화

스토리 조회 시 N+1 가능성 방지

결정Story 조회 Repository에 Spot fetch join 쿼리를 추가해 연관 장소 정보를 함께 로딩

이유추후 story 응답에 spotName, thumbnail, spotType 등이 추가되어도 추가 select가 발생하지 않도록 사전 대응

AR/도감 획득 흐름 분리

결정AR Camera는 오디오 완청 후 획득 처리, Collection 화면은 획득 여부 조회와 리뷰 역할로 분리

이유도감 상세에서 acquire를 반복 호출하면 미획득 403, 중복 획득 409가 발생할 수 있어 화면 책임을 명확히 나눔

트러블슈팅

NORMAL 가이드 fallback 실패

해결FE 로직을 바꾸지 않고 운영 DB의 누락된 NORMAL story/audio 데이터를 보강하는 관리자 동기화 API를 추가

결과현재 월 SPECIAL story가 없어도 기본 오디오 가이드가 정상 fallback될 수 있는 구조 확보

도감 Topic API 스키마 변경

해결단일 storyId 응답과 다중 storyIds 응답을 모두 처리하는 normalize 함수를 추가하고, 다중 조회 결과를 병합·중복 제거

결과같은 대주제에 속한 여러 스팟/스토리 아이템이 한 화면에 안정적으로 표시됨

카메라 합성 이미지 저장 불일치

결과사용자가 본 화면과 앱 앨범/서버/공유 이미지가 일치하도록 개선

Android 공유 시 이미지가 아닌 텍스트만 공유

해결expo-sharing 네이티브 모듈을 Dev Client에 재빌드하고, 합성 이미지 URI를 공유 payload로 전달

웰니스 창업 아이디어 진단 및 창업제안서 자동 작성 플랫폼, PREP

2026.03 — 2026.11 예정 · 5인 팀 프로젝트

ReactTypeScriptFastAPIPostgreSQLRedisRAG / Vector DB

헬스케어·웰니스 창업 아이디어의 규제·데이터 활용성·시장성을 진단하고, 근거 기반 결과 리포트와 창업제안서를 자동 생성하는 플랫폼. React 분석 리포트 화면과 공통 API 연동, FastAPI 기반 RAG 조회 흐름 설계에 함께 참여했습니다.

Case study 자세히 보기→

담당 기능

  • React 분석 리포트 화면, 공통 API 클라이언트, TypeScript 타입 및 에러 처리 유틸 구현
  • GATE PASS/FAIL 결과에 따라 규제 위험도, 데이터 확보 가능성, 시장성, BM 추천 섹션을 조건부 렌더링
  • 법령/가이드라인 근거 문서를 evidence chunk로 정제하고 RAG 검색 API 응답 구조 설계
  • Vercel 배포, CORS, 모델 artifact 반영, API 응답 변경 이슈를 백엔드 팀과 조율하며 MVP 개발 지원

기술적 의사결정

분석 리포트 호출 책임 이동

결정입력 페이지에서 결과를 sessionStorage로 넘기지 않고, ReportContainer가 sessionId 기준으로 evaluate API를 다시 호출하도록 구조화

이유새로고침이나 직접 URL 접근 시에도 리포트를 복원할 수 있게 하기 위해

PASS/FAIL 기반 화면 구성

결정GATE FAIL일 때 후속 분석 섹션을 강제로 렌더링하지 않고, FAIL 전용 안내와 근거 중심으로 화면을 구성

이유백엔드 응답에서 data_feasibility, market_feasibility, business_model이 null로 내려와도 화면이 깨지지 않도록 하기 위해

RAG 저장소 제약 대응

결정ChromaDB가 None metadata를 저장하지 못하는 제약을 고려해 write/read 양쪽에서 sentinel 값을 관리

이유페이지 정보가 없는 evidence chunk가 API 응답에서 -1이 아니라 null로 표현되어야 FE와 사용자에게 자연스럽기 때문

트러블슈팅

API 응답 필드 변경으로 리포트 화면 깨짐 위험

해결변경 가능성이 있는 필드는 TypeScript에서 optional로 정의하고, null/누락 값에 대한 fallback UI와 조건부 렌더링 적용

결과PASS/FAIL 케이스와 PR 머지 상태에 따라 응답 구조가 달라도 리포트 화면이 안정적으로 표시됨

데이터 확보 가능성 라벨 의미 반전

해결백엔드 risk_level의 의미를 확인한 뒤 LOW/MEDIUM/HIGH를 사용자 표시용 “확보 가능성” 라벨로 역매핑

결과내부 위험도 값과 사용자에게 보여주는 가능성 표현을 분리해 오해를 줄임

RAG 검색 API의 page_start/page_end sentinel 노출

해결retriever.py에 -1 sentinel을 None으로 복원하는 헬퍼를 추가해 정수 metadata도 read 단계에서 역변환

결과페이지 정보가 없는 chunk가 API 응답에서 null로 내려오도록 수정

ChromaDB query가 FastAPI 이벤트 루프를 블로킹

해결Chroma collection은 lru_cache로 재사용하고, 동기 query 호출은 asyncio.to_thread로 분리

결과요청마다 인덱스를 다시 여는 비용과 async 핸들러 블로킹 위험을 줄임

Vercel 배포 후 API 호출 실패

해결실제 생성된 Vercel 도메인을 확인하고 백엔드 CORS 허용 origin 추가를 요청

결과배포 환경에서도 api.prepwell.shop 기반 API 호출이 정상 동작하도록 수정

PDF 저장 시 스크롤 영역 내용 누락

해결인쇄/PDF 저장 모드에서는 탭과 스크롤 UI 대신 전체 리포트 섹션이 펼쳐지도록 인쇄용 렌더링 조건 조정

결과특정 탭의 현재 스크롤 위치만 저장되는 문제를 줄이고 리포트 전체 저장 흐름 개선
